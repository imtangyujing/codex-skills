# 决策记录 decisions

> 这份文件记的是「为什么这套系统长这样」。开新对话时贴这一个文件，AI 就懂整套 loop 的设计意图，不用再贴聊天记录。
> 每条都是一个已经推导清楚、可以直接用的判断，不是待讨论的想法。

---

## 1. 判别器前移：人该站在下笔之前，不是下笔之后

把生成问题转换成判别问题，是 AI 时代最重要的能力之一。判别器比生成器好 train——但这只在判别任务有可学习的真值时成立。

写作 loop 经历了三代，区别只在「人作为判别器」站在哪：

- **草稿优先（老）**：AI 先出完整初稿，人在初稿上判别纠偏。判别在「写之后」。问题：完整草稿会锚定你的判断，一段写顺的 prose 会让你舍不得它背后那个其实错了的角度；初稿写偏时，纠偏 ≈ 重写。
- **提纲优先（老）**：人读完全部素材搭提纲，AI 按约束写。判别在「写之前」，但人是瓶颈——素材一多，阅读消化全压在人身上，效率掉得厉害。
- **选题会（新）**：AI 铺素材，人精读，选题会发散角度由人取舍。判别提前到「下笔之前」，且人不再独扛阅读。

**为什么前移更好**：方向阶段是最便宜、最不会被锚定、杠杆最高的判别位置。方向错了后面一万字全废，方向对了 prose 只是执行。在选题会里，AI 是生成器（廉价地抛多个角度），人是判别器（取舍）——这是 GAN 框架最干净的应用场景，比让人去判别「这句话好不好」高了好几个量级的杠杆。

---

## 2. 强先验是双刃剑

同一个「AI 完成的强先验草稿」，在草稿优先 loop 里帮你重读出新框架（模板带你理解素材，反复重读里长出新主线），在选题会 loop 里却可能在你读透素材前就替你定调，把你对素材的理解带偏。

结论：发散阶段用**提纲**不用成稿。提纲是骨架，没有那层诱惑你的肉，你能冷静地只判断角度本身值不值。这也省 token——不用等它生成完一整篇再判别。

---

## 3. 判别器只在「有真值」时可靠

文章质量分两层：

- **有真值层（工艺/功能）**：事实准不准、有没有幻觉、句子通不通、违禁词、破折号、结构塌没塌、逻辑接不接得上。等价于代码的「跑不跑得通」。一个空白上下文 agent 能可靠 judge，自对弈能收敛。
- **无真值层（设计/原创）**：有没有纯技术解读给不出的横向映射、叙事主体是人还是机构、有没有让冷读者「咦」一下、可转述性。等价于代码的「设计好不好看」。LLM 判别器在这层不可靠，而且有系统性偏向——它会偏爱那个流畅通用的版本，因为那就是模型自己被往那儿拉的方向（文字版的「白底紫渐变」）。

所以 AI free run + 独立判别 agent，能稳定写到「事实干净、结构完整、风格合规」的合格稿（70-80 分）。到不了的是破 10 万、转 3000 的那 20 分——角度、共鸣、转述性，全落在无真值层。

**那 20 分为什么补不上**：角度不是验证任务，是生成任务。判别器只能评判生成器写出来的东西；生成器没生出那个横向映射，判别器顶多说一句「这稿有点平」，没法替你注入。而「这稿有点平」恰恰是 LLM 判别器最不可靠、最容易因宽容而放过的判断。所以这个 loop 能侦测一部分平庸，却造不出原创——原创得有人往里注。这就是人不可替代的那个函数，它在发散端的取舍，不在验收端。

---

## 4. 评分标准要加权，权重压在「模型默认会写砸、而你靠它吃饭」的维度

来自 Anthropic harness design 那篇的四条评分标准（design quality / originality / craft / functionality）。关键不是「有四条标准」，而是作者**故意做了不对称加权**：Claude 在 craft 和 functionality 上默认就能拿高分，但在 design 和 originality 上经常平庸，所以他抬高后两者的权重，把模型推向更敢冒美学风险的方向。

映射到写作：

- **工艺/功能（轻判，default pass，检出即修）**：没违禁词、没破折号西式引号、句子有气口、事实有信源、结构不塌、读者能读懂找到主线。这些 cold-reader 扫一遍标 pass 就行，不值得花判别力。fail = 基本功破了。
- **设计/原创（重判，死磕）**：这篇有没有一个纯技术解读给不出的横向映射？叙事主体是具体的人还是抽象机构？有没有一处让冷读者「咦」一下？可转述性——读者看完能不能用一句话跟朋友复述？

**还有一个机制要记住**：评分标准的措辞，光是写进去这个动作，在任何反馈发生之前就已经把生成器推离了通用默认。所以「原创性 = 有没有横向映射」这条写进 cold-reader 的 criteria，会同时塑造生成和验收两端。判别器的设计因此是最高杠杆的 artifact。

## 5. 脚手架会被模型能力吃掉，但拆除有顺序

每个脚手架组件（skill、harness、context reset、evaluator、好 prompt）都编码了一个「模型现在做不到什么」的假设。模型一变强，假设过期，组件就该拆。

**拆除顺序有规律**：先垮掉的，总是那些为「模型某个具体行为缺陷」打的补丁；为「任务本身难度」设的结构留得更久。

实例（来自 Anthropic 两篇 harness 的演化）：context reset 编码的假设是「模型会 context anxiety、需要被反复清空保护」，Opus 4.5 让这个行为缺陷自己消失了，于是 context reset 整个被拆掉。但同一篇里 evaluator 留着——因为它补的是「主观质量判断」这个任务难度，不是模型的行为怪癖。

**操作方法**：模型每次大版本更新，挑一篇难度适中、有对照数据的稿子，关掉某个节点（比如 cold-reader）裸跑，看数据掉不掉。不掉，说明这节点对当前模型在这类任务上不再 load-bearing，可以收缩；掉，留着。让数据告诉你拆哪根，不凭感觉。

但拆除是逐个组件去问「你对应的那个缺陷还在不在」，不是「模型变强了所以一切从简」。拆一根、留一根的分寸，本身就是这套方法的核心。

---

## 6. 干净可复用的 SOP 不会因为模型变强而多余

模型吞噬脚手架，吞掉的是脚手架的**具体内容**（某个写死的假设），不是脚手架的**存在**。节点本身不过期，过期的是节点里当前写死的那些假设。所以这套 loop 不是一次性搭好，是需要随模型迭代持续维护的一组节点——而维护的过程，就是不断重新设计判别节点的过程。

---

## 一句话总纲

人的工作正在从「生成」挪到「设计判别标准」。真正稀缺的不是会给目标，是会设计那个判别闸门——而在「角度」这一层，那个闸门目前还只能是你本人。
